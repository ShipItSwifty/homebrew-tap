# ShipItSwifty Homebrew Tap — Agent Guidance

This is the Homebrew tap for [ShipItSwifty](https://github.com/ShipItSwifty/shipitswifty)
tools. Its only purpose is to distribute those CLIs via `brew install`.

## Formulae

| Formula | Upstream repo | Updater workflow |
|---------|---------------|------------------|
| `shipit` | `ShipItSwifty/shipitswifty` | `update-formula.yml` |
| `app-store-connect-mcp` | `ShipItSwifty/app-store-connect-mcp` | `update-formula-app-store-connect-mcp.yml` |

Every formula here installs a **prebuilt release binary** (`bin.install "<name>"`) —
no Swift toolchain, no build from source. `url`/`sha256` point at the `macos-universal`
and Linux archives attached to the upstream GitHub release.

## Repository layout

```text
Formula/
  shipit.rb
  app-store-connect-mcp.rb
.github/
  workflows/    # Per-formula updaters, formula checks, bottle publishing
LICENSE
README.md
CLAUDE.md
AGENTS.md
```

Do not add scripts, extra Ruby files, casks, or aliases unless explicitly asked. Add a
new formula only when explicitly asked, and give it its own `update-formula-<name>.yml`.

## Updating a formula for a new release

Normally the per-formula `update-formula*.yml` workflow does this automatically:
it polls the upstream repo for a release whose `macos-universal` and Linux archives
both exist, downloads them, computes SHA256, rewrites `url`/`sha256` in the formula
and the version cell in `README.md`, and commits as `<formula> <VERSION>`.

To do it by hand (`<name>` is `shipit` or `app-store-connect-mcp`):

1. Download both release archives and compute their SHA256:

```bash
V=<VERSION>
R=ShipItSwifty/<upstream-repo>
curl -fsSL -O https://github.com/$R/releases/download/$V/<name>-$V-macos-universal.tar.gz
curl -fsSL -O https://github.com/$R/releases/download/$V/<name>-$V-linux-x86_64.tar.gz   # shipit uses -linux-static
shasum -a 256 <name>-$V-*.tar.gz
```

2. Edit `Formula/<name>.rb` — bump the tag in each `url` and replace each `sha256`.
   Remove any stale `bottle do` block from the previous release.

3. Update the formula version cell in `README.md`.

4. Validate locally before committing (see Testing section below).

5. Commit with the message `<name> <VERSION>`.

6. Run the `Bottle` workflow manually for the new version after the formula update lands on `main`.

## Testing a formula change locally

Homebrew requires the formula to be inside a registered tap. Use the local directory:

```bash
brew tap shipitswifty/tap /path/to/this/repo
brew install --build-from-source shipitswifty/tap/shipit
brew test shipitswifty/tap/shipit
# Clean up after testing:
brew uninstall shipit
brew untap shipitswifty/tap
```

For syntax and style checks without installing:

```bash
brew style Formula/shipit.rb
brew audit --new Formula/shipit.rb   # use --new only for the first release
brew audit Formula/shipit.rb         # use this for subsequent updates
```

## Formula conventions

- `desc` must be a single sentence, no trailing period, ≤ 80 characters.
- `url` points to the prebuilt `macos-universal` / Linux archive attached to the upstream GitHub release — not a source tarball.
- `sha256` must be computed from the actual downloaded archive — never guessed. The upstream release also publishes a `-checksums.txt` you can cross-check against.
- `head` always tracks the `main` branch.
- No `depends_on` / `uses_from_macos` — the archive contains a ready-to-run binary, so `install` is just `bin.install "<name>"`.
- The `test` block must assert semver-shaped `--version` output, and `--help` output where the binary supports it. Do not hardcode an exact release version in the test.
- Bottle blocks are generated by the `Bottle` workflow. Do not hand-edit bottle checksums unless recovering from automation failure.
- Each formula's `update-formula*.yml` workflow polls its upstream releases and updates the formula automatically.
- The bottle workflow intentionally targets `macos-26`, matching ShipItSwifty's current Swift toolchain requirements.

## What NOT to do

- Do not add `depends_on` / `uses_from_macos` — the formulae install prebuilt binaries.
- Do not add casks, tap commands, or aliases.
- Do not bypass the `Bottle` workflow for normal bottle publishing.
- Do not copy or reference the ShipItSwifty main repo's architecture docs here.

## Commit style

Single-line messages only:

```
shipit <VERSION>                        # version bump
app-store-connect-mcp <VERSION>         # version bump
Fix formula build arg for Linux         # bug fix
Update README install instructions      # docs
```
